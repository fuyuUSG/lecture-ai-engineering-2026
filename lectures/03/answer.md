# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：第1回は講座の用語集を持たないので、「一般的には～」とだけ答えていた。一方でapp.agentは用語集を検索してから答えた。基礎・実装・発展があり、どれか1つに取り組めば完了と返した。解答の最後には「関連する回：第1回」があった。
- `--trace` で見えたツール呼び出し（ツール名と引数）：「LoRA とQLoRAの違いは？」はsearch_glossary({'query': 'LoRA'}) と search_glossary({'query': 'QLoRA'}) の2回で、用語を1つずつ別々に検索していた。
「第2回の内容から確認問題を1問出して」はmake_quiz({'lecture': 2}) の1回。「過学習」の問題が返ってきた。
- 1つの質問での LLM 呼び出し回数（`requests`）：「LoRA とQLoRAの違いは？」はrequests=2、tool_calls=2
「第2回の内容から確認問題を1問出して」はrequests=2、tool_calls=1
- 追加したツールと、docstring に書いた説明：make_quiz(lecture: int) -> str：用語集から指定した回の用語を集めて1つ選び、「～の意味は？」という問題と答え（definition）をJSONで返す。
docstring：指定した回の用語から確認問題を1問作り、答えとともに返す。「第2回の確認問題を出して」のように、特定の回の復習問題を求められたときに使う。
--list-toolsで3つ目のツールとして表示され、uv run pytest -qは17件すべてpassedだった。

## 宿題

- 取り組んだレベル：基礎
- やったこと：app/tools.pyのsearch_glossaryのdocstringにある「queryには調べたい用語を1つだけ入れる」を「query には関係する用語をまとめて入れる」に変えた。変更前と変更後で同じ質問「LoRA とQLoRAの違いは？」を--trace付きでそれぞれ2回ずつ実行し、ツールの呼ばれ方と回答を比べた。
- 結果：
 | | 変更前（1つだけ） | 変更後（まとめて） |
  |---|---|---|
  | ツール呼び出し | search_glossary({'query': 'LoRA'})、search_glossary({'query': 'QLoRA'}) | search_glossary({'query': 'LoRA QLoRA'}) |
  | tool_calls | 2（2回とも） | 1（2回とも） |
  | requests | 2（2回とも） | 2（2回とも） |
  | input_tokens | 1344 / 1344 | 1027 / 1027 |
  | output_tokens | 167 / 169 | 295 / 222 |

変更前の回答は用語集の定義に沿った短いものだった。
変更後の回答は長くなり、用語集の定義には無い説明が加わった。正式名称（Low-Rank Adaptation、Quantized LoRA）、FP16/BF16、VRAMなど。
- 気づき・疑問：docstringの1文を変えるだけで、モデルのツールの引数の渡し方と呼び出し回数がそのまま変わった。モデルはdocstringを読んでツールの使い方を決めていることが確かめられた。
変更後は入力トークンが減った一方で、回答が長くなり用語集に無い一般知識が混ざった。まとめて検索した結果が十分でなく、モデルが自分の知識で補った可能性がある。根拠を用語集に限りたいなら、変更前の「1つだけ」の方が向いていると思う。
